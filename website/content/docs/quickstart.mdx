## One command

You need [Docker](https://docs.docker.com/get-started/get-docker/) and nothing
else. No clone, no Node project, no Python.

```bash
npx @samata-oss/cli
```

It asks for **one Speko API key**, which covers speech-to-text, the model and
text-to-speech, so there are no three separate accounts to set up.
[Speko](https://speko.ai) is a gateway for voice models, and new accounts get $10
of free credit. Create a key on [platform.speko.ai](https://platform.speko.ai/gateway/keys),
paste it. The key is checked with Speko and saved in `.env`.

**No key yet?** Press Enter to try the free demo first. The CLI gets a demo key from
Samata's demo server, which runs your first few minutes of conversation on Samata's
own Deepgram (speech) and OpenRouter (the model) accounts, so you can hear an agent
right away. Your conversation passes through that server on its way to them. When
the demo is used up, the assistant says so: add your own keys on **Provider Keys**
to keep going. If the demo server can't be reached, is busy or is full for the day,
you get the install without a key and add one the same way.

It then downloads the stack's compose file into `./samata`, generates secrets in
`.env`, starts everything from prebuilt images (control plane, worker, LiveKit and
Postgres), and opens the dashboard at [localhost:4747](http://localhost:4747). The
first run takes a few minutes while the images download.

Then:

1. **You're already signed in.** The quickstart creates a local `admin@samata.local`
   account (password `12345678`) and signs you in, so there's no sign-up step. The
   dashboard is bound to `127.0.0.1`, so only your machine can reach it.
2. **Your key is already saved** on **Provider Keys**. A Speko key runs the
   whole assistant: Meta Muse Voice Transcribe 1.0 for speech-to-text, DeepSeek
   V4.1 Flash (on Baseten) for the model, and Inworld TTS 2 for the voice. The
   free demo is saved as your Deepgram and OpenRouter key, and runs Deepgram
   Nova-3 and Aura-2 with DeepSeek V4.1 Flash; replace those two keys with your
   own when it runs out. If you skipped the prompt, add keys there. Want other
   providers (OpenAI, Cartesia, ...)? See [Bring your own models](/docs/models).
3. **You land on an assistant that's already set up**, a receptionist for a
   made-up business called Acme, running on the models above. Open its **Test** tab
   and talk to it. Edit it, or create more from **Assistants**.

```bash
cd samata
docker compose logs -f       # watch it work
docker compose down          # stop (your data is kept)
docker compose down -v       # stop and delete all data
```

Re-running `npx @samata-oss/cli` in the same folder keeps your `.env` and starts the
stack again. Options:

| Flag                   | What it does                                                      |
| ---------------------- | ----------------------------------------------------------------- |
| `[dir]`                | Install somewhere other than `./samata`.                          |
| `--port <n>`           | Dashboard port, if `4747` is taken.                               |
| `--no-start`           | Only write `docker-compose.yml` and `.env`.                       |
| `--no-open`            | Don't open the browser.                                           |
| `--speko-key <key>`    | Give the Speko key up front instead of being asked.               |
| `--demo`               | No key: use the free demo (what Enter at the prompt does).        |
| `--test`               | A separate copy on free ports, to run beside one you already have. |
| `--force`              | Download `docker-compose.yml` again.                              |
| `--ref <ref>`          | Download from a branch, tag or commit of the repo.                |
| `--compose <file>`     | Use your own compose file (a URL or a path).                      |

The prompt is skipped when there's no terminal (CI, a pipe). If `SPEKO_API_KEY` is
set in your shell, the CLI offers to use it. The key is saved to the dashboard the
first time you sign in, and only into a workspace that has no keys yet, so keys you
change on **Provider Keys** later are never overwritten.

Browser test calls work out of the box. Real phone calls need a public address, so
set up a [server](/docs/self-host) for those.

<Callout type="warn">
Keep the `.env` that `init` generates. Your database and the provider keys stored
in it can only be read with those secrets.
</Callout>

## From source

To work on Samata itself, run the infra in Docker and the apps on your machine.
You need Docker, Node.js with [pnpm](https://pnpm.io), and Python 3. This runs
everything locally with no accounts, except the model providers you choose for
your agent.

<Steps>
<Step>

### Clone the repo and start the infra

LiveKit and Postgres run in Docker. Redis is only needed for local phone calls, so it is left out here.

```bash
git clone https://github.com/samata-oss/samata.git
cd samata
docker compose up -d livekit postgres
```

</Step>
<Step>

### Start the control plane

```bash
pnpm install
cp control-plane/.env.example control-plane/.env
pnpm db:migrate && pnpm db:seed
pnpm dev                                    # http://localhost:3000
```

`db:seed` creates a sample `receptionist` agent. Open [localhost:3000](http://localhost:3000)
and sign up: **the first account becomes the owner**.

</Step>
<Step>

### Add a model provider key

Samata uses your keys, not ours. On the dashboard open **Provider Keys** and add
an OpenAI key. One OpenAI key covers the model, the transcriber and the voice
(select OpenAI for each on the assistant), or use Deepgram and Cartesia, which
the sample agent defaults to. See [Bring your own models](/docs/models).

</Step>
<Step>

### Start the worker

```bash
cd worker
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env
.venv/bin/python main.py dev
```

The worker needs no provider keys of its own. It gets the right ones from the
control plane for each call.

</Step>
<Step>

### Talk to your agent

Open an assistant on the dashboard and use its **Test** tab. Or start a session
yourself and paste the returned `url` and `token` into the
[LiveKit agents playground](https://agents-playground.livekit.io):

```bash
curl -X POST localhost:3000/api/session/start \
  -H "authorization: Bearer dev-api-key-change-me" \
  -H "content-type: application/json" \
  -d '{"assistantId": "receptionist"}'
```

</Step>
</Steps>

<Callout type="info">
Want to see the webhook lifecycle without any audio? Run `pnpm simulate:call`.
</Callout>
