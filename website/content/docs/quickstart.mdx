## One command

You need [Docker](https://docs.docker.com/get-started/get-docker/) and nothing
else. No clone, no Node project, no Python.

```bash
npx @samata-oss/cli
```

This downloads the stack's compose file into `./samata`, generates secrets in
`.env`, starts everything from prebuilt images (control plane, worker, LiveKit and
Postgres), and opens the dashboard at [localhost:4747](http://localhost:4747). The
first run takes a few minutes while the images download.

Then:

1. **Sign up.** The first account becomes the owner.
2. **Add a model provider key** on **Provider Keys**. One OpenAI key covers the
   model, the transcriber and the voice. See [Bring your own models](/docs/models).
3. **Create an assistant** and talk to it from its **Test** tab.

```bash
cd samata
docker compose logs -f       # watch it work
docker compose down          # stop (your data is kept)
docker compose down -v       # stop and delete all data
```

Re-running `npx @samata-oss/cli` in the same folder keeps your `.env` and starts the
stack again. Options:

| Flag                   | What it does                                                      |
| ---------------------- | ----------------------------------------------------------------- |
| `[dir]`                | Install somewhere other than `./samata`.                          |
| `--port <n>`           | Dashboard port, if `4747` is taken.                               |
| `--no-start`           | Only write `docker-compose.yml` and `.env`.                       |
| `--no-open`            | Don't open the browser.                                           |
| `--force`              | Download `docker-compose.yml` again.                              |
| `--ref <ref>`          | Download from a branch, tag or commit of the repo.                |
| `--compose <file>`     | Use your own compose file (a URL or a path).                      |

Browser test calls work out of the box. Real phone calls need a public address, so
set up a [server](/docs/deploy) for those.

<Callout type="warn">
Keep the `.env` that `init` generates. Your database and the provider keys stored
in it can only be read with those secrets.
</Callout>

## From source

To work on Samata itself, run the infra in Docker and the apps on your machine.
You need Docker, Node.js with [pnpm](https://pnpm.io), and Python 3. This runs
everything locally with no accounts, except the model providers you choose for
your agent.

<Steps>
<Step>

### Clone the repo and start the infra

LiveKit and Postgres run in Docker. Redis is only needed for local phone calls, so it is left out here.

```bash
git clone https://github.com/samata-oss/samata.git
cd samata
docker compose up -d livekit postgres
```

</Step>
<Step>

### Start the control plane

```bash
pnpm install
cp control-plane/.env.example control-plane/.env
pnpm db:migrate && pnpm db:seed
pnpm dev                                    # http://localhost:3000
```

`db:seed` creates a sample `receptionist` agent. Open [localhost:3000](http://localhost:3000)
and sign up: **the first account becomes the owner**.

</Step>
<Step>

### Add a model provider key

Samata uses your keys, not ours. On the dashboard open **Provider Keys** and add
an OpenAI key. One OpenAI key covers the model, the transcriber and the voice
(select OpenAI for each on the assistant), or use Deepgram and Cartesia, which
the sample agent defaults to. See [Bring your own models](/docs/models).

</Step>
<Step>

### Start the worker

```bash
cd worker
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env
.venv/bin/python main.py dev
```

The worker needs no provider keys of its own. It gets the right ones from the
control plane for each call.

</Step>
<Step>

### Talk to your agent

Open an assistant on the dashboard and use its **Test** tab. Or start a session
yourself and paste the returned `url` and `token` into the
[LiveKit agents playground](https://agents-playground.livekit.io):

```bash
curl -X POST localhost:3000/api/session/start \
  -H "authorization: Bearer dev-api-key-change-me" \
  -H "content-type: application/json" \
  -d '{"assistantId": "receptionist"}'
```

</Step>
</Steps>

<Callout type="info">
Want to see the webhook lifecycle without any audio? Run `pnpm simulate:call`.
</Callout>
